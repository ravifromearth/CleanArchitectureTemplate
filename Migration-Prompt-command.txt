Check list -
 
 
## Provider & Configuration
- Replace `System.Data.SqlClient` / `Microsoft.Data.SqlClient` with `Npgsql` (NuGet).
- Update connection string keys to `Host`, `Port`, `Database`, `Username`, `Password` (optionally `Include Error Detail=true`, `Keepalive=30`, `Maximum Pool Size`).
- In EF Core, switch `UseSqlServer(...)` to `UseNpgsql(...)` in DI configuration.
- Add `Npgsql.EntityFrameworkCore.PostgreSQL` (and optionally `.NamingConventions`, `.NetTopologySuite`).
- Regenerate EF migrations for PostgreSQL (`dotnet ef migrations add <Name>` then `database update`).
- Set default schema to `public` via `modelBuilder.HasDefaultSchema("public")` (if using schemas).
- Apply `UseSnakeCaseNamingConvention()` to avoid quoted identifiers and casing issues.
- Use `ValueGeneratedOnAdd()` to map to PostgreSQL `GENERATED ... AS IDENTITY` for PKs.
- Replace SQL Server `rowversion` with PostgreSQL `xmin` as the EF concurrency token.
- Map GUIDs to `uuid` and set default to `gen_random_uuid()` (enable `pgcrypto` or `uuid-ossp`).
 
## SQL Query & Syntax Changes
- Replace `TOP (N)` with `LIMIT N` (use `OFFSET` for paging).
- Replace `GETDATE()` with `now()` or `CURRENT_TIMESTAMP`.
- Replace `ISNULL(a,b)` with `COALESCE(a,b)`.
- Replace `LEN(x)` with `length(x)`.
- Replace `DATEDIFF(part,a,b)` with `DATE_PART('part', b - a)` or `age(b,a)`.
- Replace `NEWID()` with `gen_random_uuid()` or `uuid_generate_v4()` (extension required).
- Replace `IDENTITY` with `GENERATED ALWAYS/BY DEFAULT AS IDENTITY`.
- Replace `MERGE` with `INSERT ... ON CONFLICT (key) DO UPDATE SET ...`.
- Remove `WITH (NOLOCK)` and `READ UNCOMMITTED` hints (not supported; PG uses MVCC).
- Replace temp tables `#temp` with `CREATE TEMP TABLE ...` (or prefer CTEs and arrays/JSON).
- Replace `FOR XML` constructs with JSON (`jsonb`) queries and operators.
- Prefer `LIMIT/OFFSET` over `OFFSET … FETCH NEXT` for paging consistency.
 
## Data Type Mappings
- `uniqueidentifier` → `uuid`; `bit` → `boolean`; `datetime/datetime2` → `timestamp [with/without time zone]`.
- `nvarchar(max)/varchar(max)` → `text`; `varbinary(max)` → `bytea`; `money` → `numeric/decimal` with explicit precision/scale.
- Standardize identifiers to lowercase/snake_case or quote consistently to avoid case-folding issues.
- Review enums/value converters for provider-specific behaviors and adjust mappings.
 
## LINQ/EF Behavior
- Use `EF.Functions.ILike()` for case-insensitive string matches (PG string comparisons are case-sensitive by default).
- Replace `string.Contains()` where needed with `EF.Functions.ILike("%term%")` for case-insensitive LIKE.
- Keep `Skip(...).Take(...)` for paging (translates to `OFFSET/LIMIT` in PostgreSQL).
- Remove SQL Server–specific attributes/annotations that conflict with Npgsql conventions.
 
## Transactions & Bulk Operations
- Avoid distributed `TransactionScope` (MSDTC unsupported); use outbox/inbox or saga patterns for cross-DB workflows.
- Remove table/index hints (ignored by PostgreSQL) and revisit isolation expectations (default is `READ COMMITTED`).
- Replace `SqlBulkCopy` with Npgsql `COPY` (binary/text import via `BeginBinaryImport`/`BeginTextImport`).
- Replace TVPs with arrays, JSONB payloads, or temporary tables + COPY.
 
## Stored Procedures / Functions
- Rewrite T‑SQL stored procedures/functions/triggers to PL/pgSQL syntax (variables, loops, exceptions change).
- Call server code via `CALL proc(...)` for procedures and `SELECT fn(...)` for functions.
- Adjust return types and OUT parameters per PL/pgSQL semantics.
 
## Indexing & Performance
- Remove the notion of clustered indexes; design PK/secondary indexes explicitly for access patterns.
- Convert filtered indexes to partial indexes (`CREATE INDEX ... WHERE is_active = true`).
- Use `CREATE INDEX ... INCLUDE (colA, colB)` where covering indexes help.
- Add GIN/GiST indexes for JSONB/FTS/spatial; enable `pg_stat_statements` and analyze plans.
- Run `VACUUM (AUTO)`/`ANALYZE` tuning as needed post‑migration for healthy planners.
 
## JSON, Full‑Text, Spatial
- Prefer `jsonb` for semi‑structured data and use operators (`@>`, `->`, `->>`, `?`, `#>>`).
- Use full‑text search with `to_tsvector`/`to_tsquery` (consider GIN indexes and language configs).
- Enable PostGIS and `UseNetTopologySuite()` for spatial types in EF/Npgsql.
 
## Date/Time & Time Zones
- Store UTC times in `timestamptz` and set `.NET` `DateTime` to UTC or use `DateTimeOffset`.
- Replace `GETUTCDATE()` with `now()` or `CURRENT_TIMESTAMP AT TIME ZONE 'UTC'` as appropriate.
- Validate conversions at API boundaries (client/server and serialization).
 
## Security & Extensions
- Enable required extensions per environment: `pgcrypto`, `uuid-ossp`, `citext`, `postgis` (as needed).
- Recreate users/roles/grants in PostgreSQL (no direct analog to SQL Server logins/Windows auth).
- Replace Integrated Security with username/password or SSL‑based auth per org policy.
 
## DevOps & Configuration
- Use official `postgres:<version>` images and configure health checks in containers/k8s.
- Move secrets to your secret store and update CI/CD variables for PostgreSQL DSNs.
- Configure connection resilience (`EnableRetryOnFailure()`) and timeouts (`statement_timeout`, `idle_in_transaction_session_timeout`).
- Verify connection pool settings (size/keepalive) under real workloads.
 
## Observability & Diagnostics
- Hook Npgsql logging into `Microsoft.Extensions.Logging` and APM (OpenTelemetry/App Insights).
- Enable and monitor `pg_stat_statements` for slow query insight and index tuning.
- Use `Include Error Detail=true` during migration/debugging and remove for production.
 
## Testing & Validation
- Re‑run unit/integration tests and update fixtures for type/case differences.
- Validate edge cases for NULL vs empty strings, Unicode text, bytea, and precision/scale.
- Compare key business queries between SQL Server and PostgreSQL for performance and results equivalence.
